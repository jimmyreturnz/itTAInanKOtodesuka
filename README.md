# tAIkoMapper

Generates osu!taiko charts from audio, with controllable difficulty and style.

A latent diffusion model in the shape of MuG-Diffusion, adapted for taiko: a
KL-autoencoder compresses charts into a latent sequence, and a conditional 1D
U-Net denoises that latent while attending to a multi-scale mel encoding of the
song. Difficulty, note density, style and the beat grid are all inputs.

**Start here: [docs/MANUAL.md](docs/MANUAL.md)** — what to run, in order.
**Why it is built this way: [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md)**

---

## How it works

```
.osu  ---------> chart [6, T]  ---(VAE)--->  z [16, T/16]
audio ---------> mel [128, T]  ---(encoder)-> features, one per U-Net level
tempo ---------> timing [3, T]  sin/cos beat phase + downbeat

  z_t + t + audio + timing + (difficulty, style, density, motif)
        --(U-Net)--> v          DDIM + classifier-free guidance
        --(VAE)-->   chart      --> .osz
```

Everything runs on a single 20 ms time grid: one mel frame is one chart frame.
That contract lives in `taiko/data/frames.py` and is asserted at load, because
breaking it does not raise or spoil the loss curve — it just quietly produces a
model that ignores the music.

### Design decisions worth knowing

**The beat grid is an input, not an output.** Tempo is known at generation
time, so the model is told where the beats are rather than having to invent
them and be corrected afterwards. It arrives as continuous sin/cos phase, which
carries sub-frame timing that a pulse train cannot — that precision is what 1/4
and 1/6 snaps need.

**Audio features land on the U-Net's own resolutions.** A strided stem takes
the mel down to latent resolution with learned pooling, plus a max-pooled
spectral-flux branch so transients survive the 16x reduction. Interpolating
across that gap instead would point-sample away most of the onset information,
at exactly the level that decides where notes go.

**Style is a 16-dimensional motif vector**, quantised to 8 buckets and dropped
per-dimension during training. It is measured on the same window the model must
generate, which makes it nearly a summary of the answer; without that
corruption the model learns to read the answer off its own conditioning and
generation collapses when a user supplies a rough vector instead.

**Whole songs are generated by MultiDiffusion** — overlapping windows denoised
in parallel with their predictions averaged at every step, so they share one
latent instead of being stitched together afterwards.

## Quick start

```bash
pip install -r requirements.txt

# 1. Your PC: turn an osu! Songs folder into shards to upload
python scripts/pack_dataset.py --scan "D:/osu!/Songs"

# 2. Kaggle: notebooks/kaggle_train.ipynb  (2x T4)
#      stage 1  autoencoder   ~8 GPU-hours     Gate A: onset F1 >= 0.98
#      stage 2  diffusion     150-250 hours    Gate B: onset F1 >  0.40

# 3. Your PC: make a map
python scripts/generate.py --audio song.mp3 --difficulty 5.5 --preset stream
```

Style can also be copied from a map you like:

```bash
python scripts/generate.py --audio song.mp3 --difficulty 6 \
    --reference "Songs/12345 Song/Song [Oni].osu"
```

## Gates

Two hard stops. Both exist because the failure they catch is invisible in the
loss curve.

| Gate | Measure | Threshold | Why |
|---|---|---|---|
| **A** | Autoencoder onset F1 at +/-1 frame | >= 0.98 | Whatever the first stage loses is a permanent ceiling |
| **B** | Diffusion onset F1 on held-out audio | > 0.40 | Separates following the music from emitting plausible rhythms |

```bash
python scripts/evaluate.py --n-maps 40
```

Neither replaces playing the maps. Import ten into osu! at every milestone.

## Layout

```
taiko/data/       time grid, parsing, chart tensors, shards, motif vector
taiko/model/      autoencoder, audio encoder, U-Net, scheduler, sampling
taiko/eval/       chart quality metrics
scripts/          pack_dataset, train_autoencoder, train_diffusion,
                  evaluate, generate
notebooks/        Kaggle training notebook
tests/            run any file directly: python tests/test_dataset.py
```

`tests/test_dataset.py` is the important one. It writes each frame's index into
a synthetic mel and reads it back out of a training window, which is the only
direct proof that audio and charts describe the same milliseconds.

## Requirements

Python 3.10+, PyTorch 2.0+. Training assumes two T4s (Kaggle); a single GPU
works with `--single-gpu`. Preprocessing is CPU-only and needs no GPU at all.
